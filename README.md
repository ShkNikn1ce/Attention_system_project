# Система тестирования внимания пилотов по методике Шульте

Веб-приложение авиакомпании для оценки внимания пилотов. Психолог назначает проверку, пилот проходит пять таблиц Шульте, система считает показатели ЭР, ВР и ПУ, психолог формирует заключение о допуске к полётам, администратор ведёт нормы и сводные отчёты.

Приложение написано на Django 5.2 и Python 3.12. Данные хранятся в SQLite. Интерфейс на русском языке, часовой пояс — `Asia/Novosibirsk` (UTC+7).

## Запуск

```text
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py seed
python manage.py runserver
```

Сайт открывается на http://127.0.0.1:8000/ и слушает только этот компьютер.

Команда `seed` создаёт персонал и нормы допуска, если их ещё нет. Пилотов она не добавляет: список пилотов после установки пуст.

| Роль | Как появляется | Логин | Пароль |
| --- | --- | --- | --- |
| Администратор | команда `seed` | `admin` | `admin123` |
| Авиационный психолог | команда `seed` | `psy` | `psy12345` |
| Пилот | регистрация на `/register/` или карточка администратора | задаёт сам | не короче 6 символов |

Повторный запуск `seed` не меняет пароли уже существующих учётных записей.

Проверки:

```text
python manage.py test schulte
```

Каталог `attention_system` — предыдущая консольная реализация на стандартной библиотеке. Её тесты запускаются отдельно:

```text
python -m unittest discover -s tests -t .
```

## Архитектура

Проект следует схеме Django MVT. Это тот же набор обязанностей, что у MVC, с другими именами: модель хранит данные, view обрабатывает запрос, шаблон показывает страницу.

| Слой | Каталог | Назначение |
| --- | --- | --- |
| Проект | `config/` | настройки, корневые адреса, точки входа WSGI и ASGI |
| Модель | `schulte/models.py` | сущности и ограничения базы |
| Правила | `schulte/services.py` | формулы, допуск, динамика, отчёт |
| View | `schulte/views.py`, `schulte/urls.py` | сценарии и проверка роли |
| Формы | `schulte/forms.py` | проверка ввода |
| Шаблон | `schulte/templates/schulte/` | страницы |
| Оформление | `schulte/static/schulte/app.css` | стили |
| Начальные данные | `schulte/management/commands/seed.py` | персонал и первая норма |

Чужая роль получает страницу «Операция недоступна» с кодом 403. Неавторизованный запрос уходит на страницу входа.

## Роли и доступ

В системе три роли. Одна учётная запись принадлежит ровно одной роли.

**Пилот** регистрируется сам либо его заводит администратор. Он проходит назначенное тестирование, смотрит свои результаты и уведомления. Чужие сессии ему недоступны.

**Авиационный психолог** входит готовой учётной записью. Он назначает проверку, смотрит результаты любого пилота, пишет заключение о допуске и строит динамику.

**Администратор** входит готовой учётной записью. Он ведёт карточки пилотов, нормы допуска и сводные отчёты, видит журнал передач в службу безопасности полётов. Учётная запись `admin` также является суперпользователем Django, поэтому ей доступна служебная админка `/admin/`.

Персонал через открытую регистрацию не создаётся. Форма регистрации всегда создаёт пользователя с ролью «пилот». Логин, уже занятый сотрудником, повторно занять нельзя.

## Вход

Страница `/login/` принимает логин и пароль. Пароль хранится только как хэш Django (PBKDF2).

Неверный логин и неверный пароль считаются одинаково: «Неверный логин или пароль», затем предлагается повторить ввод. Счётчик ведётся по строке логина, даже если такого пользователя нет. После трёх неудач следующий вход блокируется сообщением «Превышено число попыток входа» — в том числе с верным паролем. Успешный вход до исчерпания попыток обнуляет счётчик. Сброс блокировки в интерфейсе не предусмотрен: запись лежит в таблице `LoginThrottle`, пока её не удалят из базы.

Выход выполняется только запросом POST, чтобы чужой сайт не мог разлогинить пользователя ссылкой.

## Сущности

Все сущности живут в приложении `schulte`. Пользователь — собственная модель `User` на базе `AbstractUser`, она указана в `AUTH_USER_MODEL`.

### Пользователь

Общие поля: логин, хэш пароля, роль, ФИО, время последнего входа. У пилота дополнительно есть уникальный табельный номер и должность. У персонала табельный номер пустой. На экране показывается ФИО, а если его нет — логин.

Удаление пилота запрещено, если у него есть сессии тестирования или строки сводных отчётов: внешние ключи стоят в режиме `PROTECT`. Уведомления удаляются вместе с пользователем.

### Норма допуска

Шесть границ: минимум и максимум для ЭР, ВР и ПУ. Нижняя граница не может быть больше верхней. Действующей считается последняя созданная норма.

`seed` создаёт первую норму, если норм ещё нет: ЭР 3–25, ВР 0,8–1,1, ПУ 0,8–1,1. Границы включительные: значение ровно на границе считается нормой.

Если действующая норма ещё не использована ни в одном заключении, новое сохранение переписывает её. Если по ней уже есть заключение, создаётся новая версия, а старая остаётся привязанной к своим заключениям.

### Сессия тестирования

Одно назначение: пилот, назначивший психолог, дата и время, тип проверки и статус.

Типы проверки: плановая, периодическая, предполётная. Методика по умолчанию — «Шульте».

Статусы:

```text
назначена → завершена
назначена → отменена
```

Завершённую сессию нельзя отменить, отменённую нельзя завершить. Новая сессия создаётся в статусе «назначена». Если у пилота несколько назначенных сессий, он проходит самую раннюю.

### Таблица Шульте

Одна таблица внутри сессии: порядковый номер от 1 до 5, размер стороны, расположение чисел, сами числа и время в секундах.

Размер в интерфейсе — 3×3, 4×4 или 5×5. В базе размер не меньше 2. Числа — перестановка от 1 до n². «По порядку» оставляет их как есть, «вперемешку» перемешивает. В одной сессии не может быть двух таблиц с одним номером. Время строго больше нуля.

### Результат тестирования

Один результат на сессию: ЭР, ВР и ПУ. Появляется вместе с переводом сессии в статус «завершена», одной транзакцией с пятой таблицей.

### Заключение о допуске

Решение психолога по результату. Хранит психолога, норму, которая действовала в момент решения, дату, комментарий и одно из трёх решений:

- годен;
- годен с ограничением;
- направлен на дополнительное обследование.

Автоматическое предложение знает только два исхода: все три показателя внутри нормы — «годен», иначе — «направлен на дополнительное обследование». «Годен с ограничением» психолог выбирает сам, поверх предложения. Повторно заключение по той же сессии через интерфейс не создаётся: показывается уже сохранённое.

### Сводный отчёт и строка отчёта

Отчёт администратора за период. Строка — один пилот, у которого в этом периоде есть завершённые сессии: ФИО на момент отчёта, число сессий и средние ЭР, ВР, ПУ. Пилот без сессий в периоде в отчёт не попадает. Строки сортируются по ФИО.

### Уведомление

Сообщение пилоту. Сейчас создаётся при назначении проверки: ФИО, тип проверки и дата. Непрочитанные считаются в меню. Открытие страницы уведомлений помечает их прочитанными.

### Передача в службу безопасности

Журнал факта, а не внешний вызов. Запись появляется при сохранении заключения и при формировании отчёта. Администратор видит последние 50 записей.

## Показатели

Сессия состоит ровно из пяти таблиц. Времена обозначаются T1…T5, в секундах, в порядке предъявления.

```text
ЭР = (T1 + T2 + T3 + T4 + T5) / 5
ВР = T1 / ЭР
ПУ = T4 / ЭР
```

ЭР — эффективность работы, среднее время. Чем меньше, тем быстрее пилот находил числа. ВР — врабатываемость: отношение времени первой таблицы к среднему. ПУ — психологическая устойчивость: отношение времени четвёртой таблицы к среднему.

Расчёт отклоняется, если таблиц не пять или какое-либо время не положительное. На экране ЭР показывается с двумя знаками после запятой, ВР и ПУ — с тремя.

## Как проходит тестирование

1. Психолог выбирает пилота и тип проверки. Сессия сохраняется, пилот получает уведомление.
2. Пилот открывает «Тестирование». Если назначенной сессии нет, тест не начинается.
3. Пилот выбирает размер и расположение чисел и подтверждает готовность.
4. Сервер генерирует таблицу и запоминает момент показа. Живой счётчик на странице только отображает время; в базу пишется интервал сервера от показа до отправки.
5. Пилот нажимает числа строго по возрастанию, с 1 до n². Чужое число подсвечивается и не засчитывается. Обновить страницу можно: та же таблица и тот же отсчёт сохраняются в сессии браузера.
6. После пятой таблицы считаются ЭР, ВР и ПУ, сессия становится завершённой.
7. Кнопка «Прервать тестирование» переводит сессию в «отменена» и удаляет уже сохранённые таблицы. Результат при этом не создаётся.

Для нажатий на клетки нужен JavaScript. Последовательность всё равно проверяет сервер: отправить можно только числа 1…n² по порядку.

## Сценарии по ролям

### Пилот

| Страница | Поведение |
| --- | --- |
| `/register/` | Создаёт пилота. Логин, ФИО и табельный номер обязательны, пароль не короче 6 символов, логин и табельный номер уникальны. После успеха — возврат ко входу. |
| `/` | Назначенная проверка, последние уведомления и пять последних результатов. |
| `/testing/` | Старт теста или сообщение, что проверка не назначена. |
| `/results/` | Завершённые свои сессии. Чужой идентификатор даёт 404. |
| `/notifications/` | Список уведомлений. |

### Психолог

| Страница | Поведение |
| --- | --- |
| `/assign/` | Назначение проверки. Если пилотов нет, форма не показывается. |
| `/reviews/` | Список пилотов, затем их завершённые сессии, время каждой таблицы и показатели. |
| `/reviews/session/<id>/conclusion/` | Предложение по действующей норме. Без результата или без нормы заключение не создаётся. Решение можно скорректировать и дополнить комментарием. Сохранение передаёт заключение в журнал службы безопасности. |
| `/dynamics/<id>/` | Точки ЭР, ВР и ПУ по дате и три графика. Меньше двух завершённых сессий — сообщение о недостатке данных. |

### Администратор

| Страница | Поведение |
| --- | --- |
| `/pilots/` | Список, создание, изменение и удаление. Пустое ФИО, занятый логин, занятый табельный номер и короткий пароль отклоняются. При изменении пустой пароль оставляет прежний хэш. Пилота с сессиями или со строками отчёта удалить нельзя. |
| `/norms/` | Действующая норма, форма новых границ и история версий. |
| `/reports/` | Период и группа пилотов. Начало позже конца, пустая группа и отсутствие завершённых сессий в периоде отклоняются. Готовый отчёт передаётся в журнал службы безопасности. |
| `/security/` | Журнал заключений и отчётов. |
